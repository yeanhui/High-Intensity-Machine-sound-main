How it works

  • Model: Xenova/ast-finetuned-audioset-10-10-0.4593, an Audio Spectrogram Transformer fine-tuned on AudioSet (527 sound-event classes: engines, alarms, sirens, tools, mechanical fans, speech, etc.), run entirely client-side via transformers.js (ONNX Runtime Web / WebAssembly). No audio ever leaves your device.
  • Pipeline: microphone audio is captured with the Web Audio API, resampled to 16 kHz mono in-browser, accumulated into a rolling ~2s window, and classified about once per second (throttled to stay responsive on CPU-only hardware).
  • Each class gets an independent confidence score (0–100%) — multiple sounds can be "true" at once (e.g. "Engine" and "Vibration" together), unlike a single-label classifier.
  • The alert banner fires when any predicted label contains one of your alert keywords (Alarm, Siren, Explosion, …) above the confidence threshold — both tunable in Settings.
  • The event log keeps a timestamped history of the top detection each cycle; Export CSV downloads it.
  • The live spectrum and spectrogram panels are a direct read of the microphone signal (via a Web Audio AnalyserNode) independent of the AI model — useful for visually spotting tonal shifts, rattles, or sudden spikes at a glance.
  • Set healthy baseline (Live tab) captures the current spectral "fingerprint" while the machine runs normally. Afterward, every cycle computes a baseline deviation % — a simple, unsupervised anomaly score independent of the AI labels — and can trigger its own alert (threshold in Settings). This is how the app can flag "something sounds different" even for sounds AudioSet has no specific category for (e.g. a developing mechanical fault).

Limitations

  • AudioSet's classes are general-purpose, not manufacturing-specific — there's no dedicated "bearing wear" class; it recognizes broad categories (Engine, Mechanical fan, Vibration, Rattle, Alarm) that correlate with machine condition.
  • Runs fully in the browser on the CPU: the model (~100MB) downloads once and is cached, but the first load and first inference can take tens of seconds.
  • Browser microphones are consumer-grade and band-limited (~20 kHz) — the same limitation as the DSP-only reference project this repo also contains.
  • The baseline deviation score is a simple spectral-shape distance, not a trained anomaly model — it's sensitive to background noise changes and microphone position, so re-capture the baseline if you move the mic or the environment changes significantly.
